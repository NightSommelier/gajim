# Правила участі у розробці (Contributing)

Якщо ви хочете створити форк та долучитися до розробки Gajim, приєднуйтесь до нашого групового чату підтримки [xmpp:gajim@conference.gajim.org?join](xmpp:gajim@conference.gajim.org?join).

[English Documentation](CONTRIBUTING.md)

---

## Версіонування

```text
┌────── Major (змінюється лише при зміні версії GTK)
│ ┌───── Minor (змінюється з додаванням нових функцій)
│ │ ┌──── Micro (використовується для хотфіксів та дрібних змін)
│ │ │ ┌─── Використовується лише під час розробки
│ │ │ │
1.3.3-dev1
```

## Гілки

Наразі використовується одна основна гілка — `master`.
Гілка `master` завжди повинна перебувати у робочому стані, придатному для випуску релізу.
Розробка великих змін має відбуватися у тематичних гілках (feature branches) або окремих форках.

---

## Пул-реквести (Pull Requests)

Створюйте пул-реквести до гілки `master` із окремих цільових гілок. Опишіть видимі для користувача зміни, платформи, яких це стосується, та проведені перевірки. Не включайте сторонні зміни форматування або згенеровані артефакти збирання.

Не додавайте паролі, токени доступу, закриті ключі, сертифікати підпису або конфіденційні звіти про вразливості до комітів, описів чи логів CI. Для повідомлень про безпеку дотримуйтесь інструкцій у [SECURITY_UK.md](SECURITY_UK.md).

Для розробки на NixOS або іншій системі з Nix використовуйте середовище:

```bash
nix-shell .github/nix/shell.nix
uv sync
uv run python -m pytest -q
uv run ruff check
uv run ruff format --check
uv run codespell
```

## Форматування повідомлень комітів (Commit Messages)

Кожне повідомлення коміту повинно починатися з одного з таких префіксів:

**Для списку змін (Changelog):**
- `feat` — додано новий функціонал
- `fix` — виправлено помилку
- `perf` — оптимізація швидкодії
- `imprv` — покращення наявного функціоналу
- `change` — зміна наявної поведінки

**Службові префікси:**
- `new` — новий внутрішній код без видимих змін для користувача
- `ci` — зміни у пайплайнах CI/CD
- `cq` — покращення якості коду (форматування, типізація)
- `cfix` — внутрішні виправлення коду, що не входять до changelog
- `refactor` — рефакторинг коду
- `chore` — регулярні технічні завдання
- `release` — коміти підготовки релізу
- `revert` — скасування попередніх комітів
- `other` — інші зміни

Перша літера опису після двокрапки повинна бути великою:
`feat: New Button which does something`

## Використання pre-commit

Встановіть pre-commit у кореневому каталозі репозиторію:

```bash
pip install pre-commit
pre-commit install
```

## Довідкові сторінки (Man Pages)

Сторінки man пишуться у форматі Markdown та конвертуються за допомогою `pandoc`:

```bash
pandoc gajim.1.md -s -t man -o gajim.1
```
